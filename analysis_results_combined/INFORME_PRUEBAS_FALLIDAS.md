### Descripción de las Causas Raíz Principales:
1. **Desajuste de Tipos / Modelos de Datos en Problemas Estructurales (`P03`, `P05` y `P07` en Scala y Java — 132 casos):**
   * **`P03 Flatten Nested List` en Scala (42 fallos):** El test unitario invoca `Solution.flatten(List(1, List(2, 3)))` pasando un `List[Any]` heterogéneo. Cuando los modelos diseñan un tipo algebraico propio (`enum NestedList[+A]` en Scala 3 o `sealed trait Nested` en Scala 2) en lugar de recibir `List[Any]`, el compilador `scalac` rechaza la llamada con `type mismatch; found: List[Any], required: Solution.NestedList[?]`.
   * **`P05 Transaction Pipeline` en Java (43 fallos) y Scala (40 fallos):** Los tests unitarios construyen las transacciones como diccionarios dinámicos (`List<Map<String, Object>>` en Java y `List[Map[String, Any]]` en Scala). En cambio, en lenguajes de tipado estático, los modelos tienden a modelar el dominio creando un `record Transaction(String id, double amount, ...)` en Java 17/21 o `case class Transaction(...)` en Scala. Esto produce incompatibilidad de firma estática frente al `Map` del test, mientras que en **Python (`P05` = 98.1 % de éxito)** los diccionarios son el estándar idiomático.
   * **`P07 2D Flood Fill` en Scala (28 fallos):** En Scala los modelos alternan entre `Array[Array[Int]]` (mutable) y `Vector[Vector[Int]]` o `List[List[Int]]` (inmutables funcionales), generando colisión de tipos cuando la firma no coincide con la estructura 2D esperada por `P07FloodFillSpec`.
2. **Restricción de Compilación Histórica en Java 8 (`--release 8` — 38 fallos en Java 8):**
   * Al compilar bajo `-Dmaven.compiler.release=8`, el compilador bloquea cualquier llamada a `List.of(...)`, `Map.of(...)` (introducidos en Java 9) o `var` (Java 10).
3. **Fallos en Ejecución / Lógica / Tipado Dinámico (25 casos: 23 en Free vs. 2 en Paid):**
   * **`ChatGPT Free (GPT-4o mini)` concentra 21 de los 25 casos de esta categoría:**
     * **Pila LIFO invertida en `P03 Flatten Nested List` (5 casos — Java 17/21 iterativo y Python 3.9/3.11/3.14 iterativo):** En Java (`ratio = 0.60`), `GPT-4o mini` apila en orden directo sin invertir al insertar en el `Deque`/`Stack`, devolviendo `[4, 5, 6, 2, 3, 1]` en lugar de `[1, 2, 3, 4, 5, 6]`. En Python (`ratio = 0.0`), invierte dos veces (`reversed(item)` al apilar y además `result.reverse()` al final), fallando su propio `assert` en tiempo de carga del módulo (`AssertionError`).
     * **Pérdida de desplazamiento en `P02 Binary Search` funcional en Java (2 casos — `P02_java_17_funcional` y `P02_java_21_funcional`, `ratio = 0.29`):** Divide la lista con `subList` en la llamada recursiva pero devuelve un índice erróneo o `-1` cuando el elemento está presente.
     * **Paréntesis sin cerrar y Flood Fill en Scala 3 (`P04_scala_3.3/3.6_funcional` con `ratio = 0.88`, y `P07_scala_3.6_funcional/iterativo` con `ratio = 0.0` — 4 casos):** En `P04`, no verifica que la pila quede vacía al terminar la cadena (`TC07 - Sin cerrar` devuelve `true` en vez de `false`).
     * **`IndentationError` en bloques `def` de Python (`P07_python_*` en 9 archivos y `P05_python_3.11_to_3.14` en 1 archivo — 10 casos):** El cuerpo de `def flood_fill(...)` y `def process_transactions(...)` carece de sangría en la primera línea tras los dos puntos (`IndentationError: expected an indented block after function definition`).
   * **`Gemini Free (3.5 Flash)` registra 2 casos en Python (`P03_python_3.11_funcional` y `P03_python_3.14_funcional`):** Incrusta una sentencia `match item: case ...` dentro de una expresión `lambda acc, item: acc + (match item: ...)` (`SyntaxError: invalid syntax`, dado que `match` en Python es una sentencia y no una expresión).
   * **`ChatGPT Plus (GPT-6)` registra 2 casos en 189 pruebas (`P03_python_3.11_funcional` y `P03_python_3.11_iterativo`):** Declara el alias recursivo `NestedList: TypeAlias = list[int | "NestedList"]` sin `from __future__ import annotations`; en Python 3.11+, el operador `|` en tiempo de ejecución entre `type` (`int`) y `str` (`"NestedList"`) lanza `TypeError: unsupported operand type(s) for |: 'type' and 'str'`.
   * **`Claude Free (Sonnet 5)`, `Claude Pro (Opus 5.5)` y `Gemini Pro (3.1 Pro)` registraron 0 fallos en Python (100 % de éxito, 63/63 cada uno) y 0 fallos lógicos en los 3 lenguajes.**
